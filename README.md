# AWS Site-to-Site VPN Terraform Module

Terraform module which creates a site-to-site IPsec VPN on a transit gateway:

- `aws_customer_gateway` for the remote device
- `aws_vpn_connection` attached to the transit gateway, two tunnels with one set of IKE/IPsec options
- `aws_ec2_transit_gateway_route` for each remote CIDR (static routing)
- a CloudWatch log group for tunnel IKE/IPsec logs (optional)
- a `TunnelState` alarm per tunnel (optional)

## Usage

```hcl
module "site_to_site_vpn" {
  source = "git::https://github.com/kloia/platform-modules.git?ref=module/aws-site-to-site-vpn/v0.1.0"

  name                        = "prod-partner"
  customer_gateway_ip_address = "203.0.113.10"

  transit_gateway_id             = "tgw-0123456789abcdef0"
  transit_gateway_route_table_id = "tgw-rtb-0123456789abcdef0"
  remote_cidrs                   = ["172.31.100.0/24"]

  tunnel_options = {
    ike_versions                 = ["ikev2"]
    phase1_encryption_algorithms = ["AES256", "AES256-GCM-16"]
    phase1_integrity_algorithms  = ["SHA2-256", "SHA2-384"]
    phase1_dh_group_numbers      = [14, 19, 20]
    phase2_encryption_algorithms = ["AES256", "AES256-GCM-16"]
    phase2_integrity_algorithms  = ["SHA2-256", "SHA2-384"]
    phase2_dh_group_numbers      = [14, 19, 20]
    dpd_timeout_action           = "restart"
    startup_action               = "start"
  }

  tunnel_alarm_actions         = [aws_sns_topic.alarms.arn]
  tunnel_alarm_actions_enabled = false # until the remote side brings the tunnels up
}
```

A complete example is in [`examples/transit-gateway-static`](examples/transit-gateway-static).

## Notes

- **Static routing needs `remote_cidrs`.** A static VPN propagates nothing into a transit gateway route table, so the
  module adds a static route per remote CIDR. With BGP (`static_routes_only = false`), turn on
  `transit_gateway_route_table_propagation` instead.
- **Leave association off on a transit gateway with default association enabled.** AWS already associates the attachment
  with the default route table, and declaring the same association fails at apply. Turn it on for a non-default table.
- **The VPC side is not in this module.** Subnet route tables still need a route to the remote CIDRs via the transit
  gateway, and security groups the ports the remote side uses.
- **The tunnel log group is `/aws/vendedlogs/site-to-site-vpn/<name>`.** The VPN service writes its own CloudWatch Logs
  resource policy for it, and AWS recommends the `/aws/vendedlogs/` prefix to keep that policy under its size limit.
- **Pin `tunnel_options`.** Unset options keep the AWS defaults, which include DH group 2 and SHA1. The remote device has
  to be configured with a matching custom policy.
- **Pre-shared keys are in state** (sensitive), whether generated by AWS or passed in `tunnel_preshared_keys`.
- **Alarms treat missing data as breaching**, so a tunnel that stops reporting alarms rather than going quiet. Both tunnels
  are DOWN until the remote side is configured: apply with `tunnel_alarm_actions_enabled = false` first.

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| `name` | Name for the connection; prefixes the customer gateway, VPN connection, log group and alarm names. | `string` | n/a | yes |
| `tags` | Tags added to every resource. | `map(string)` | `{}` | no |
| `customer_gateway_ip_address` | Public IPv4 address of the remote VPN device. | `string` | n/a | yes |
| `customer_gateway_bgp_asn` | ASN of the remote device. AWS requires one even for static routing, where it is not negotiated. | `number` | `65000` | no |
| `customer_gateway_device_name` | Optional name of the remote device, for reference only. | `string` | `null` | no |
| `transit_gateway_id` | Transit gateway the VPN attaches to. | `string` | n/a | yes |
| `static_routes_only` | Use static routing. Set false for BGP, which also makes remote_cidrs unnecessary. | `bool` | `true` | no |
| `local_ipv4_network_cidr` | Remote-side CIDR the tunnels carry (the IPsec traffic selector). Null means 0.0.0.0/0. | `string` | `null` | no |
| `remote_ipv4_network_cidr` | AWS-side CIDR the tunnels carry (the IPsec traffic selector). Null means 0.0.0.0/0. | `string` | `null` | no |
| `tunnel_inside_cidrs` | Optional inside /30s from 169.254.0.0/16, [tunnel1, tunnel2]. AWS picks them when empty. | `list(string)` | `[]` | no |
| `tunnel_preshared_keys` | Optional pre-shared keys, [tunnel1, tunnel2]. AWS generates them when empty; either way they are stored in state. | `list(string)` | `[]` | no |
| `tunnel_options` | IKE/IPsec options applied to both tunnels. Unset keys keep the AWS defaults, which include weak proposals (DH group 2, SHA1); pin them to what the remote device supports. | `object` | `{}` | no |
| `transit_gateway_route_table_id` | Transit gateway route table that receives remote_cidrs, and the association/propagation when enabled. | `string` | n/a | yes |
| `remote_cidrs` | Remote CIDRs routed to the VPN attachment. Required for static routing. | `list(string)` | `[]` | no |
| `transit_gateway_route_table_association` | Associate the attachment with transit_gateway_route_table_id. Leave false on a transit gateway with default association enabled. | `bool` | `false` | no |
| `transit_gateway_route_table_propagation` | Propagate the attachment into transit_gateway_route_table_id. Only BGP routes propagate. | `bool` | `false` | no |
| `create_tunnel_log_group` | Create a log group for tunnel IKE/IPsec logs, shared by both tunnels. | `bool` | `true` | no |
| `tunnel_log_group_arn` | Existing log group for tunnel logs when create_tunnel_log_group is false. Null disables tunnel logging. | `string` | `null` | no |
| `tunnel_log_retention_in_days` | Retention of the created tunnel log group. | `number` | `90` | no |
| `tunnel_log_kms_key_id` | Optional KMS key ARN for the created tunnel log group. | `string` | `null` | no |
| `create_tunnel_alarms` | Create one TunnelState alarm per tunnel. | `bool` | `true` | no |
| `tunnel_alarm_actions` | ARNs notified on ALARM and OK, usually an SNS topic. | `list(string)` | `[]` | no |
| `tunnel_alarm_actions_enabled` | Whether the alarms notify. Tunnels stay DOWN until the remote side is configured, so set false for the first apply. | `bool` | `true` | no |
| `tunnel_alarm_period` | Seconds per evaluation period. | `number` | `300` | no |
| `tunnel_alarm_evaluation_periods` | Consecutive DOWN periods before the alarm fires. | `number` | `2` | no |

## Outputs

| Name | Description |
|------|-------------|
| `customer_gateway_id` | Customer gateway ID. |
| `vpn_connection_id` | VPN connection ID. |
| `transit_gateway_attachment_id` | Transit gateway attachment ID of the VPN. |
| `tunnel1_address` | AWS-side outside IP of tunnel 1, for the remote device. |
| `tunnel2_address` | AWS-side outside IP of tunnel 2, for the remote device. |
| `tunnel1_inside_cidrs` | Inside addresses of tunnel 1: AWS side and remote side. |
| `tunnel2_inside_cidrs` | Inside addresses of tunnel 2: AWS side and remote side. |
| `tunnel_log_group_name` | Name of the created tunnel log group, or null. |
| `tunnel_alarm_arns` | TunnelState alarm ARNs by tunnel. |
